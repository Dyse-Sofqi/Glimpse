**Bug fixes**

- **Fixed the group drag handle not reordering**: the original implementation relied on setPointerCapture to retarget subsequent pointermove events to the handle, but the handle node is moved within the DOM mid-drag and capture proved unreliable in some environments, dropping move events so dragging did nothing; move/up listeners now live on **window** (no capture involved — events can't be lost), with edge auto-scroll near the list's top/bottom and suppression of the browser-emitted click after a drag so it can't mis-trigger the accordion
- **Fixed the volume button sometimes failing to open the slider (same intermittent dead clicks on play/pause and mode buttons)**: bottom-bar and floating button icons were unconditionally rebuilt on every state push (~4/s during playback) — when a push landed between mousedown and mouseup, the svg being pressed was removed from the DOM and the browser never dispatched the click for that press; icons are now **only rebuilt when they actually change**; also fixed the volume popup's outside-close listener leak (registered as mousedown but removed as pointerdown, so it was never detached and kept accumulating) by standardizing on pointerdown and excluding the volume button itself from the "outside" check (the toggle previously relied on the button stopping mousedown propagation)
- **Fixed the local playlist's grouped list turning transparent on hover**: the group headers' and song rows' hover background used `--background-modifier-hover`, which is a semi-transparent theme color (`color-mix(…, transparent)`) — hovering made rows and the sticky group header show the panel background through them, looking "hollow"; both now use the opaque `--background-secondary-alt` step of the theme scale (light `#fcfcfc` / dark `#333333`), keeping the raised-hover feedback while every other hover effect (row shadow, cover play overlay fade-in, header ⋯ button reveal) stays unchanged
- **Fixed lyrics auto-scroll snapping back the instant you scroll up**: every timeupdate used to drag the current line back to center as soon as it left the viewport, and the per-line rebuild (`empty()`) also threw the viewport to the top of the list — so scrolling up to read earlier lyrics was yanked back immediately; manual scrolling (wheel / touch / scrollbar drag) now pauses auto-follow, keeps the viewport pinned while lines advance (restored by anchor, no jump) and resumes automatically once the current line is fully back in view (changing songs or re-entering the lyrics pane also resumes)
- **Fixed the teleprompter being lifted after an Obsidian restart**: the position clamp was computed from the window height (`y = min(y, vh - h)`), and since that height depends on the current content, any content-height change unrelated to position shoved the whole window upward — on restart the constructor runs before any document is active (empty content, short window) so the saved y survived, but once the document opened and the real content rendered taller, the width auto-fit re-placed the window and clamped y up (and the new y was persisted, so every restart climbed further). The vertical clamp now only keeps the window's top on screen (never height-based), and content that does not fit is bounded by a content-area height cap (`min(70vh, space below the window)`) that scrolls internally; changing the font size no longer moves the window either, and dragging still keeps the whole window inside the viewport


#### 1.0.8 (2026-09-15)

**New features**

- **The custom-CSS field is now a CodeMirror 6 editor**: syntax highlighting, auto-closing brackets and quotes, undo history, and **CSS autocompletion as you type** (property names, value keywords, selector tag names). The panel pops up while typing or on demand with Ctrl/Cmd-Space, and accepting a property also inserts the colon and a space. The completion data comes from `@codemirror/lang-css`, so it tracks the CSS spec without hand-maintained lists (+29 KB bundle)
- **New "Description" field for persistent highlighters**: a note about what the expression matches — display-only, never used for matching. It sits on the row below the name in settings and on the line below the expression in the list card, and survives import/export and clipboard round-trips
- **Settings form re-flowed**: the search-term/expression field and its regex toggle now occupy their own row (they previously shared a row with the name and color swatch), and the "Clear current edit", "Import from clipboard" and "Save" buttons moved next to the name and swatch
- **New "Clear current edit" button** (lucide `refresh-ccw`): resets the whole form to its initial state (name, description, swatch, search term, regex toggle, mark toggles, custom CSS) — no more clearing every field by hand when you want to abandon an edit
- **Teleprompter font weight extended to 100–900** (was 300–700), adding 100 Thin, 200 Extra Light, 800 Extra Bold and 900 Black
- **No default background color any more**: new highlighters start with no color; saving without picking one stores an empty `color`, and the static highlighter simply skips the background (the highlight class still applies, so custom CSS can take over)

**Fixes**

- **Fixed "dragging the color-picker knob does nothing, dragging outside it works"**: the knob (`.pcr-picker`) and the interactive surface (`.pcr-palette` / `.pcr-slider`) are **siblings**, not parent and child, in Pickr's template. - **Minimap**: Document minimap on the right side of the editor (similar to VS Code minimap), supports drag-to-scroll, click-to-jump, wheel sync, independently toggleable
- **Full-document search**: Selection matching no longer limited to visible viewport, uses `SearchCursor` to scan entire document
- **Match line collection decoupled from decoration limit**: All match line numbers collected before decoration cap, scrollbar markers cover entire document regardless of `maxMatches`
- **Reverse selection fix**: Normalize `from`/`to` boundaries for leftward drags (anchor > head), preventing `sliceDoc` from returning empty
- **Debounce fix**: Fixed delay stuck at 0ms — `highlightDelay` Facet combine strategy changed from `Math.min` to `Math.max`
- **Stale setTimeout guard**: `clearVersion` counter prevents old `setTimeout` callbacks from wiping fresh decorations
- **Settings persistence**: `minSelectionLength` and `maxMatches` forcibly aligned with `DEFAULT_SETTINGS`, stale data.json values auto-written back on load
- **Chinese + English comments**: Added comprehensive comments in `selection.ts` and `scrollbar-markers.ts`

- **Plugin rename**: Consolidated `GazerPlugin` → `GlimpsePlugin` across all files, CSS classes (`modal-gazer` → `modal-glimpse`), and export filenames (`gazer.json` → `glimpse.json`)
- **Fixed new highlighters not activating after save**: `static.ts` used non-standard `Array.prototype.contains()` (returned `undefined`) causing saved highlighters with explicit `mark: ["match"]` to silently fail — replaced all 7 occurrences with `.includes()`
- **Settings UI inline style → CSS refactoring**: Removed all `setAttribute("style")` calls per Obsidian plugin review guidelines; using CSS custom properties (`--picker-bg`) and classes (`.glimpse-modal-input`, `.highlighter-name`); added corresponding rules in `styles.css`
- **Import from clipboard**: New button before Save (clipboard-copy icon) — pastes JSON from clipboard and populates the entire form (name, color, query, regex, mark toggles, custom CSS editor with automatic dark/light theme)
- **Per-highlighter export**: New button between Edit and Delete (clipboard-paste icon) — exports a single highlighter as JSON via ExportModal
- **New "match" toggle in creation form**: Defaults to ON, giving clear visual feedback that the highlighter will be active after saving; line/start/end/group toggles remain OFF by default
- **Toolbar button rename**: "导入" → "一键导入" (One-click Import), "导出" → "一键导出" (One-click Export)
- **Code cleanup**: `regexp-cursor.ts` whitespace and formatting normalization
